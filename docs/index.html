Mail

Inbox, drafts, sent items, archive, and trash come from the server, including folders you added there. A reply fills the message view. Search looks through the words of mail already on this computer, bodies included, and lists whole conversations; Search deeper asks the server.

Calendar

Work week, week, and month share one grid. Accept, decline, or mark a meeting tentative. Notes stay with the event.

People

Each mailbox brings its contacts. A contact you add in Mailroom is created on that account.

What this version is

Version 1.3.4 runs on Linux. There is no installer package yet, so you build it from source. It is not Microsoft Outlook. Microsoft mail, calendar, and contacts go through Microsoft Graph, and Google accounts through the Gmail and Google Calendar APIs, each with an application you register yourself.

A reply shows the full email address next to the friendly name. The word Draft is red. Settings shows the version along the bottom. Recurring-meeting editing, and creating or renaming folders, are not in this build.

Install

You need a Linux desktop, Rust, and WebKitGTK 4.1. Clone github.com/jonspinks/mailroom. You need access to that repository.

  1. Install the system libraries

    These are the Tauri 2 packages for a desktop build. Other distributions need the same WebKitGTK 4.1, GTK 3, and OpenSSL libraries. The Tauri prerequisites list them.

    Arch 
    sudo pacman -S --needed webkit2gtk-4.1 base-devel curl wget file openssl appmenu-gtk-module libappindicator-gtk3 librsvg xdotool
    Debian and Ubuntu 
    sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev

  2. Install Rust

    Skip this if cargo is already on your path.

    curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh

  3. Build and run

    Run these from the repository root. The first build compiles the desktop shell and takes a while. Later builds are short.

    git clone https://github.com/jonspinks/mailroom.git
cd mailroom
cargo build --release --manifest-path src-tauri/Cargo.toml
./src-tauri/target/release/mailroom

    The page is index.html, styles.css and app.js; each build copies them into dist/. Run scripts/mailroom-update later to pull, build and restart.

Sign in to Microsoft

Mailroom is a public client. You register an application id in Microsoft Entra and you do not create a client secret.

  1. Register the application

    In the Entra admin centre, open App registrations and create a registration.

    • Supported accounts: any organisational directory and personal Microsoft accounts. The app uses the common sign-in endpoint.
    • Add a platform: Mobile and desktop applications. Redirect URI: http://localhost. The app listens on a free localhost port, and that redirect matches it.
    • Under Authentication, allow public client flows.
    • Add these delegated permissions: offline_access, User.Read, Mail.Read, Mail.ReadWrite, Mail.Send, Calendars.ReadWrite, Contacts.Read, Contacts.ReadWrite, MailboxSettings.ReadWrite.

    A work tenant may ask an administrator to grant those permissions. Copy the application (client) id. It is a GUID. Do not paste a secret into Mailroom.

  2. Add the account

    Open Settings in Mailroom, save the application id, then add the account. A browser opens for Microsoft sign-in, so xdg-open has to work. The sign-in is stored in the desktop keyring, under the service name mailroom. A locked keyring cannot save the account.

    The application id is kept in ~/.config/mailroom/client-id. Mail already downloaded is kept in ~/.config/mailroom/mail.db.

Sign in to Google

Gmail and Google Calendar accounts sign in through an OAuth client you make in Google Cloud, much as Microsoft accounts use your Entra app. Personal Gmail and Google Workspace accounts both work.

  1. Make the Google client

    • In the Google Cloud console, create a project, then turn on the Gmail API and the Google Calendar API under APIs & Services.
    • Set up the OAuth consent screen (Google Auth Platform). Audience: External for a personal account, or Internal if every account is in one Workspace. Add yourself as a test user.
    • Under Data Access, add the scopes gmail.modify, calendar.events and calendar.calendarlist.readonly.
    • Under Clients, create an OAuth client of the Desktop app type. Copy its client ID and secret, or download its JSON file.

    While an External app is in Testing, Google signs it out every seven days. Publish it (In production) to keep you signed in; Google then shows an unverified-app warning at sign-in, which you can pass, for up to 100 users. A Workspace administrator may also need to allow the app.

  2. Add the account

    In Mailroom, add an account and choose Google. Paste the client ID and secret, or the whole JSON file into the first box, then sign in in the browser and leave every permission ticked. The client is kept in ~/.config/mailroom/google-client.json; the sign-in goes in the keyring with the others.

    Gmail labels are folders here. Each message has one folder: Inbox while it is in the Inbox, its label once it is archived, and Archive when it has no label. Move to a folder files it under that label. Categories, rules, automatic replies, send later, contacts and who's free are for Microsoft accounts for now.
